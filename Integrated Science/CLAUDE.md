# CLAUDE.md — ExamForge (통합과학 기출 재구성 파이프라인)

> 이 파일은 `claude_ExamForge_통합과학_에이전트_설계서.md`(v0.2)를 구현 단계로 옮긴 운영 규칙이다.
> 설계서는 **왜**를 설명하고, 이 파일은 **어떻게 행동할지**를 규정한다. 두 문서가 충돌하면 설계서의 최신 버전을 우선하고, 이 파일을 갱신한다.

## 0. 프로젝트 현황 스냅샷 (2026-09-02 기준)

- `/inbox`에 마더텅 편집 PDF 원본이 이미 존재한다. 파일명 규칙은 `{연도}년-{월}월-{학년}-{과목}-{문제|해설}.pdf`로 **일관되어 있음을 확인** — 설계서 O1(파일명 파싱 가능 여부)은 해결된 것으로 간주하고 `probe_pdf.py`는 이 패턴을 1차 파싱 규칙으로 사용한다.
- `/inbox`에는 통합과학 외 과목(물리학1·화학1·생명과학1·지구과학1, 2019~2025 고2, 2015 개정 선택과목)도 섞여 있다. **사용자 확인(2026-09-02): 통합과학과 내용이 겹치므로 자산 후보로 사용 가능.** A0에서 이 파일들을 제외하지 않는다. 단, 이 4개 과목은 통합과학과 **별도의 2015 성취기준 체계**를 쓰므로 B1 매핑 범위를 확장해야 한다 — 자세한 내용은 아래 "매핑 범위 확장" 항목 참조.
- `2028학년도-통합과학-수능예시문항-1차/2차.pdf`는 2022 개정 교육과정 기준으로 새로 집필된 문항이며 **사용자 확인: 사용 가능.** C9(신설 영역 `과학의 기초`·`과학과 미래 사회` 조달)의 1순위 후보 자산으로 A0/D0에서 우선 검토한다. 출처가 한국교육과정평가원 예시문항으로 시·도교육청 학평 기출과 저작권 주체가 다르므로, E2 각주에는 출처를 구분해 표기한다(C6 문구와 별개로 확인 필요).
- **매핑 범위 확장 (신규 요구사항, 설계서에 없던 항목)**: 물리학Ⅰ·화학Ⅰ·생명과학Ⅰ·지구과학Ⅰ 문항을 문항은행에 넣으려면, B1의 `standards_map.json`이 "2015 통합과학 ↔ 2022 통합과학1·2" 1쌍만이 아니라 **"2015 물리학Ⅰ/화학Ⅰ/생명과학Ⅰ/지구과학Ⅰ 각각 ↔ 2022 통합과학1·2"** 4쌍을 추가로 커버해야 한다. `/.claude/skills/curriculum-ref/references/`에 해당 4개 과목의 2015 성취기준 전문이 **아직 없음 — 구현 착수 전 확보 필요**(신규 미결 항목, §4 실행 전에 사람에게 확인).
- **item_id 체계 보강 필요**: 설계서 §1.6은 `item_id = {연도}{월}_{학년}_{원본번호}`(예: `202403_H1_07`)로 정의하는데, 여러 과목이 섞이면 같은 연·월·학년·원본번호가 과목별로 중복될 수 있다(예: 2019년 3월 고2 물리학Ⅰ 7번과 화학Ⅰ 7번). **과목 코드를 반드시 포함**하도록 `{연도}{월}_{학년}_{과목코드}_{원본번호}`(예: `201903_H2_PHY1_07`)로 확장한다. `crop_manifest.json`·`item_bank.json` 스키마에 반영.
- **소프트 제약 변경(2026-09-02, 사용자 지정)**: "회차당 동일 출처 자산 문항 수"는 **목표 2, 불가피할 때만 3까지**(절대 상한은 3 유지, 4개부터 위반)로 세분화했다. `blueprint.json`의 `constraints.soft.preferred_same_source_exam_per_set`(=2)·`max_same_source_exam_per_set`(=3), xlsx `기준` 시트 B80/D80, `회차1~3` 시트 S열 검증 수식(`COUNTIFS`, >3에서 경고)에 반영 완료. **회차 간에는 적용되지 않는다** — 같은 자산이 다른 회차에 더 많이 쓰여도 무방하며, 회차 하나 안에서만 지킨다. 실제 회차1은 16개 자산에 걸쳐 전부 ≤2로 구성해 3을 한 번도 쓰지 않았다.
- **물리학Ⅰ/화학Ⅰ/지구과학Ⅰ 선택과목 실사용 확인(2026-09-02)**: 위 "매핑 범위 확장" 항목에서 미결로 남겨뒀던 선택과목 자산을 실제로 회차1에 투입했다(2019~2025 고2 3월 자산 적극 사용 — 사용자 지정). item_id 과목코드 체계(PHY1/CHM1/ESS1/INTG)가 실제로 문항 3개 이상 섞이며 정상 작동함을 확인. 단, "매핑 범위 확장"에서 지적한 2015 성취기준 4과목분 전문 미보유 문제는 여전히 미해결이며, 이 자산들의 G열(2015 매핑)도 다른 문항과 동일하게 공란(대기) 처리했다.
- `blueprint.json`이 프로젝트 루트에 있다 — 최종 위치는 `/output/canon/blueprint.json`이어야 한다(§3 폴더 구조 참조). **아직 이동하지 않았다.** 이동 시 내용을 변경하지 말 것(GATE-3 승인·잠금 완료본).
- `/source`, `/config`, `/.claude/skills`, `/.claude/agents`, `/output` 디렉터리는 아직 생성되지 않았다. 구현 순서는 §4(설계서) — **자산 1개 크롭 검증 전에는 다른 코드를 작성하지 않는다.**

## 1. 역할 정의

메인 에이전트(이 세션)는 **오케스트레이터**다. 판단이 필요한 작업은 아래 4개 서브에이전트에 위임하고, 메인은 다음만 수행한다:

- 현재 파이프라인 단계 판정 (§8)
- 게이트 통과 여부 확인 및 차단 (§2)
- 서브에이전트 호출과 산출물 경로 전달 (§4, §5)
- 사람에게 보고·승인 요청

| 서브에이전트 | 책임 | 참조 스킬 |
|---|---|---|
| **asset-ingestor** | PDF 진단(A0)·크롭(A1)·정답 파싱(A2)·자산 QC(A3) | pdf-probe, item-cropper, answer-key-parser, contact-sheet |
| **item-tagger** | 성취기준 매핑(B1)·문항 태깅(C1~C3) | curriculum-ref |
| **set-composer** | 블루프린트 역산(B2, 완료됨)·선정(D1)·배점(D2)·배열(D3) | set-composer-tools |
| **publisher** | 엑셀·시험지 PDF·최종 QC(E1~E3) | exam-publisher, contact-sheet |

메인 에이전트 스스로 문항을 태깅하거나 성취기준을 매핑하지 않는다 — 반드시 해당 서브에이전트를 호출한다(컨텍스트 오염 방지가 이유, 설계서 §3.3).

## 2. 게이트 규칙 (GATE-1~6)

각 게이트는 사람의 명시적 승인 없이는 통과할 수 없다. 메인 에이전트는 게이트 통과 여부를 **파일 존재 검사**로 판정하며, 절대 "아마 괜찮을 것"이라고 추정하지 않는다.

| 게이트 | 위치 | 통과 조건 | 통과 표식 |
|---|---|---|---|
| GATE-1 | A3 이후 | 자산 QC 컨택트시트를 사람이 육안 검토 | `output/qc/.approved_assets` |
| GATE-2 | B1 이후 | `standards_map.json` 사람 승인 (canon) | `output/canon/.approved_standards` |
| GATE-3 | B2 이후 | `blueprint.json` 승인 — **이미 완료·잠금됨(v0.2)** | `output/canon/.approved_blueprint` |
| GATE-4 | C3 이후 | 무작위 10% 샘플 + `tag_confidence: low` 전건 사람 검토 | `output/canon/.approved_tagging` |
| GATE-5 | D2 이후 | 배점 재배정안 사람 승인 | `output/canon/.approved_scoring` |
| GATE-6 | E3 이후 | 최종 QC 체크리스트 승인 → `/output/final/`로 이동 허가 | 사람의 명시적 "승인" 응답 |

**차단 방식**: 게이트 미통과 시 다음 단계 서브에이전트를 호출하지 않는다. 사람이 승인하지 않았는데 하위 단계 산출물을 생성했다면 그 자체가 오류이며 즉시 롤백(파일 삭제 또는 격리)한다.

## 3. canon 우선 원칙

`standards_map.json`과 `blueprint.json`은 **canon**이다 — 이 둘이 승인·잠금되기 전에는 C/D/E 단계(태깅·선정·조판)에 물리적으로 진입하지 않는다.

- 진입 전 반드시 `/output/canon/.approved_standards`, `/output/canon/.approved_blueprint` 두 플래그 파일의 존재를 확인한다.
- `blueprint.json`은 v0.2에서 이미 확정되었으므로 **재역산하지 않는다.** 루트의 `blueprint.json`을 `/output/canon/blueprint.json`으로 옮기고 `.approved_blueprint` 플래그만 생성하면 된다(내용 재검토는 사람이 원할 때만).
- `standards_map.json`은 아직 생성 전이다 — `confidence != high` 항목 전건에 대해 사람 검토를 받기 전에는 승인 플래그를 만들지 않는다.
- canon 파일은 승인 후에도 **수정 시 재승인 절차를 다시 밟는다**(플래그 삭제 후 재검토).

---

## 4. 서브에이전트 호출 규칙

- 메인 에이전트만 서브에이전트를 호출한다. **서브에이전트 간 직접 호출은 금지**한다 — 서브에이전트가 다음 단계가 필요하다고 판단하면 메인에게 결과를 반환하고, 메인이 다음 서브에이전트를 호출한다.
- 한 번에 하나의 서브에이전트만 활성화한다. 병렬 실행은 동일 단계 내 배치 작업(예: item-tagger의 10문항 배치)에 한해 허용하며, 서로 다른 Phase를 병렬로 돌리지 않는다.
- 서브에이전트 호출 전, 반드시 선행 게이트 통과 여부를 메인이 먼저 확인한다.

---

## 5. 데이터 전달 규칙

- 서브에이전트에는 **파일 경로와 처리 대상 ID 목록만** 전달한다. 문항 이미지나 성취기준 전문을 프롬프트에 인라인으로 붙여넣지 않는다(컨텍스트 낭비, 설계서 §3.3의 서브에이전트 분리 이유와 동일).
- 유일한 인라인 전달 예외: 사람의 게이트 응답(승인/반려 텍스트, §9 형식)은 짧으므로 그대로 전달한다.
- 서브에이전트의 출력은 항상 파일에 쓰고, 메인은 그 경로만 받아 다음 단계에 넘긴다.

## 6. 금지 사항

- **수량·합계·중복을 눈대중(LLM 판단)으로 확인하지 않는다.** 25문항 카운트, 50점 검산, 3회차 간 중복 검사는 반드시 스크립트(`validate_selection.py` 등)로 한다.
- **문항을 창작하지 않는다.** ExamForge는 기존 기출의 선별·재조합·조판만 한다(설계서 §1.2 비목적).
- `/output/final/`에 직접 쓰지 않는다. 산출물은 항상 `/output/staging/`에 먼저 쓰고, GATE-6 승인 후에만 이동한다.
- `/source`(원본 PDF)를 수정하지 않는다. 읽기 전용으로 취급한다.
- 신설 영역(과학의 기초·과학과 미래 사회) 문항에 `source_year ≥ 2025` 하드 제약(C9)을 완화하지 않는다. 재고 부족 시 완화로 우회하지 말고 반드시 에스컬레이션한다(D0).
- 정답 미상 문항을 선정 후보에 포함하지 않는다.
- 2015→2022 매핑에서 `dropped` 판정 문항을 태깅 단계 이후 임의로 되살리지 않는다 — 이는 교사 판단 영역(O5)이므로 사람에게 명시적으로 묻는다.

## 7. 로깅 규칙

모든 단계의 시작·종료·완화(relaxation) 발생을 `/output/logs/run_<timestamp>.jsonl`에 append한다. 각 레코드는 최소한 다음을 포함한다:

```json
{"ts": "ISO8601", "phase": "A1", "event": "start|end|relax|escalate|skip", "detail": "..."}
```

- 완화가 발생한 단계(D1 소프트 제약 완화, D3 배열 규칙 완화 등)는 반드시 어떤 제약을 어떤 순서로 완화했는지 기록한다.
- 스킵된 자산·문항은 사유와 함께 기록하여 나중에 추적 가능하게 한다.

## 8. Cowork 세션 재개 절차

세션 시작 시 메인 에이전트는 다음 순서로 **현재 단계를 자동 판정**하고 사람에게 보고한다:

1. `/output/canon/.approved_blueprint`, `.approved_standards` 존재 여부 확인 → canon 잠금 상태 파악
2. `/output/item_bank.json`의 태깅 완료 문항 수 확인 → C단계 진행률 파악(10문항 배치 기준)
3. `/output/selection.json`, `/output/scoring_proposal.md`, `/output/arrangement.json` 존재 여부 → D단계 진행 지점 파악
4. `/output/staging/`, `/output/final/` 존재 여부 → E단계 및 GATE-6 여부 파악
5. 판정 결과와 "다음 할 일"을 사람에게 먼저 보고한 뒤 작업을 재개한다. 임의로 앞 단계를 건너뛰거나 되돌리지 않는다.

세션이 중간에 끊긴 배치(예: 태깅 10문항 중 일부만 처리)는 `item_bank.json`에 이미 append된 문항을 기준으로 **미처리분부터 재개**한다.

## 9. 실패 처리 매트릭스

| 단계 | 실패 유형 | 처리 |
|---|---|---|
| A0 | 파일명 연·월·학년 파싱 실패 | 표지 첫 200자 추출 → 에이전트 판단 보완 → 그래도 실패 시 에스컬레이션 |
| A1 | 자산당 문항 수 불일치 | `vision` 전략으로 자동 재시도(최대 2회) → 실패 시 해당 자산 스킵 + 로그 |
| A2 | 정답표 파싱 실패 | 에스컬레이션(수기 입력 요청). 정답 없는 문항은 선정 후보에서 영구 제외 |
| A3 | 컨택트시트 육안 검토에서 결함 발견 | 문제 `item_id` 목록 받아 A1 해당 문항만 재실행 |
| B1 | 매핑 실패/애매 | **재시도 없음.** 에스컬레이션 전용 — 교육과정 해석은 교사 판단 영역 |
| D0 | 신설 영역 재고 부족 | **완화 금지.** 에스컬레이션 — 신규 자산 추가/직접 제작/블루프린트 편차 조정 중 사람이 선택 |
| C1~C3 | 스키마 검증 실패 | 자동 재시도 최대 2회 → 3회째 실패 시 스킵 + `eligible: false` |
| C1~C3 | 난이도 자기검증 순위 역전 | 해당 배치만 재태깅 |
| D1 | 하드 제약 위반으로 해 없음 | 소프트 제약을 ⑧→⑥→⑦→⑤ 순으로 1단계씩 완화. 하드 제약(①~④)은 절대 완화하지 않음. 최대 완화에도 해 없으면 에스컬레이션 |
| D3 | 배열 규칙 만족 실패 | R6→R4 순 완화 후 자동 재시도(최대 50회 셔플) → 실패 시 최선해 채택 + 로그 |
| E1 | 엑셀 검증 실패 | 자동 재시도 1회 → 실패 시 에스컬레이션 |
| E2 | 문항이 페이지 경계에서 잘림 | 이미지 축소율 조정 후 자동 재시도(최대 3회) → 실패 시 페이지 강제 분할 |

원칙: **재시도는 결정론적 처리 오류(스크립트 단)에만 적용**하고, 교육과정 해석·신설 영역 조달처럼 판단이 필요한 실패는 재시도하지 않고 곧바로 에스컬레이션한다.

## 10. 저작권 및 이용 범위 고지 (C6)

- 학평 기출 저작권은 각 시·도교육청에, 마더텅 편집물 저작권은 출판사에 있다.
- 모든 산출물은 **교실 수업 목적의 내부 이용**으로 한정한다. 온라인 공개, 배포, 판매를 하지 않는다.
- 최종 시험지 PDF(E2) 하단 각주에 이용 범위 고지 문구를 반드시 삽입한다.
- 이 프로젝트 파일 일체(`/output/final` 포함)를 외부 서비스에 업로드하거나 공유 링크로 배포하지 않는다.
